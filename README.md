# TermVisualization-BGA

Небольшое приложение на C++17 и SDL2 для просмотра STL-модели и температурных датчиков. Модель и точки растеризуются на CPU, а SDL2 создаёт окно и передаёт события мыши и клавиатуры. На Linux приложение получает температуры в отдельном потоке через SocketCAN. Целевая платформа — Raspberry Pi Zero W v1.1 с Raspberry Pi OS 32-bit и CAN-контроллером MCP2515.

## Данные

- Модель: `data/model.stl`.
- Датчики: `data/sensors.csv`, столбцы `id, x, y, z, kernel, panel, address, bus, max-temp`. Столбец `kernel` задаёт индекс группы датчика для отображения (от 0 до 34); датчики без группы всегда отображаются.
- Координаты CSV задаются в системе модели после переноса центра её габаритов в начало координат. Приложение одинаково масштабирует модель и координаты CSV, не сдвигая CSV повторно.
- При запуске программа предупреждает о точках датчиков за пределами габаритов STL.
- При сборке модель STL и CSV встраиваются в программу; запуск не требует отдельных файлов с данными. Показывается столько датчиков, сколько записей в CSV.
- До первого принятого показания точка отображается нейтральным цветом, а температура — `N/A`. CAN-данные изменяют только температуру и время её последнего обновления; координаты остаются загруженными из CSV.
- SocketCAN — API ядра Linux, сторонняя CAN-библиотека не нужна. Физический CAN-интерфейс для сборки не требуется. Если выбранный интерфейс недоступен или приложение собрано не на Linux, визуализатор выводит предупреждение и продолжает работу; для запуска без приёма используйте `--no-can`.

## CAN-протокол температур

Приложение принимает стандартные кадры Classical CAN 2.0 с 11-битными CAN-ID из параметра `can-ids` в `config.txt` и DLC `8`. По умолчанию настроен адрес `0x3C0`. Один кадр содержит температуры двух датчиков; CAN-ID не кодирует группу датчиков.

| Байты | Содержимое                                  |
| ----- | ------------------------------------------- |
| 0     | ID первого датчика                          |
| 1–2   | Температура первого датчика: LSB, затем MSB |
| 3     | ID второго датчика                          |
| 4–5   | Температура второго датчика: LSB, затем MSB |
| 6–7   | Зарезервированы и игнорируются              |

ID датчика передаётся непосредственно в кадре и соответствует столбцу `id` в `data/sensors.csv`. Допустимы ID от `1` до `107`; `0` обозначает незанятый слот. Некорректный ID или ID, отсутствующий в CSV, пропускается независимо от второго слота.

Температура — 16-битное число SIGN-MAGNITUDE в Little Endian: бит 15 задаёт знак (`0` — плюс, `1` — минус), биты 0–14 содержат модуль. Значение умножается на `0.001 °C`; смещения нет. Например, `64 00` (`0x0064`) означает `+0.100 °C`, `64 80` (`0x8064`) — `−0.100 °C`, `E8 03` (`0x03E8`) — `+1.000 °C`, `E8 83` (`0x83E8`) — `−1.000 °C`.

По умолчанию используется Little Endian. Чтобы читать температуру в Big Endian (сначала MSB, затем LSB), запустите программу с `--can-byte-order big`. Значение `little` явно включает Little Endian; также принимаются варианты `big-endian` и `little-endian`.

SocketCAN устанавливает фильтры только для настроенных стандартных CAN-ID, независимо от CSV. Расширенные, RTR, ошибочные кадры, кадры с DLC не равным 8 и CAN FD не обрабатываются. Приём выполняется в отдельном потоке; ошибка CAN не закрывает окно визуализатора.

## Управление

- Зажмите левую кнопку мыши над моделью и двигайте мышь, чтобы вращать её.
- Перетаскивайте ползунок справа, чтобы менять прозрачность модели.
- Кнопка **AUTO PERSPECTIVE** в левом верхнем углу вьюпорта устанавливает удобный ракурс обзора модели: угол X = 70°, Y = 0°, Z = −44,5°, расстояние = 18.0.
- В нижней трети основного окна (под моделью) находится блок **KERNEL** с 35 переключателями (0–34), расположенными в 7 колонок по 5 строк. Клик по переключателю включает/выключает видимость всех датчиков этого ядра на модели. Датчики без ядра всегда отображаются.
- Справа от переключателей ядер в нижней трети находятся два ползунка:
  - **MODEL TRANSPARENCY** — меняет прозрачность STL-модели.
  - **MODEL Z OFFSET** — смещает модель по вертикальной оси (Z) вверх/вниз.
- В правой панели находится список датчиков, сгруппированных по ядрам. Кнопка **COLLAPSE ALL KERNELS** над списком свертывает/разворачивает все ядра одновременно. Рядом с каждым ядром стоит стрелка `+` (развёрнуто) или `-` (свёрнуто). Клик по стрелке разворачивает/сворачивает список датчиков этого ядра.
- Клавиши `PageUp` и `PageDown` листают список на 1 строку. Колёсико мыши над списком также прокручивает его.
- В правом нижнем углу отображается общее количество датчиков (`sensors: 107`).
- Клавиши `+` и `-` или колёсико над моделью меняют масштаб.
- `Page Up` и `Page Down` прокручивают список датчиков; колёсико над списком
  также прокручивает его.
- `Esc` закрывает приложение.

## Raspberry Pi OS (32-bit)

Инструкция предназначена для Raspberry Pi Zero W v1.1 и 32-битной PiOS (ARMHF).

### Сборка проекта

Откройте Terminal (ctrl+alt+T) в рабочем столе PiOS, обновите систему при необходимости и установите зависимости: Git, компилятор, CMake, SDL2 и утилиты для диагностики CAN:

```bash
sudo apt update
sudo apt full-upgrade -y
sudo apt install -y git build-essential cmake pkg-config libsdl2-dev can-utils
```

Склонируйте репозиторий в каталог `/home/user/git/TermVisualization-BGA-`. (или любой другой по вашему желанию).
Необходимо включить SSH-сервер в raspi-config.
Для SSH-клонирования на Raspberry Pi заранее добавьте публичный SSH-ключ Pi в настройки GitHub (**Settings → SSH and GPG keys → New SSH key**, тип **Authentication Key**):

```bash
mkdir -p /home/user/git
cd /home/user/git
git clone git@github.com:qyopw/TermVisualization-BGA-.git
cd TermVisualization-BGA-
```

### Проверка CAN-интерфейса

Убедитесь, что SPI и драйвер подключённого MCP2515 настроены в Raspberry Pi OS. После загрузки системы ядро должно создать сетевой интерфейс `can0`:

```bash
ip -details link show can0
```

В выводе проверьте тип `can`, состояние интерфейса и его скорость. Скорость должна совпадать с настройкой CAN-шины. Если интерфейс найден, но выключен, поднимите его после настройки скорости:

```bash
sudo ip link set can0 up
ip -details -statistics link show can0
```

Посмотреть поступающие кадры можно через `candump` (шина должна быть подключена, а CAN-узлы настроены на одинаковую скорость):

```bash
candump can0
```

Если `can0` не найден, проверьте настройки SPI/Device Tree для конкретного MCP2515 и сообщения драйвера:

```bash
ip link show
dmesg | grep -iE 'mcp251|can'
```

Если программа сообщает об ошибке открытия сокета или привязки, проверьте, что интерфейс существует и активен, а у пользователя есть системные права для CAN RAW sockets. Ошибка CAN не закрывает окно визуализатора.

### Обновление проекта и пересборка

После отправки изменений с компьютера разработки обновите исходники на Pi и
пересоберите приложение:

```bash
cd /home/cpt/git/TermVisualization-BGA-
git pull
./rebuild.sh
```

Скрипт `rebuild.sh` находится в корне репозитория. Он переходит в каталог
проекта, конфигурирует сборку CMake в режиме `Release` и компилирует приложение
в один поток. Если сборка завершилась ошибкой, скрипт останавливается.

Если скрипт не запускается с ошибкой `Permission denied`, добавьте право
исполнения:

```bash
chmod +x rebuild.sh
```

Запускайте программу из Terminal, открытого в графическом рабочем столе, не
через SSH или текстовую консоль: для SDL2 требуется активный графический сеанс.
При конфигурации CMake файлы `data/model.stl` и `data/sensors.csv` встраиваются
в исполняемый файл.

После изменения файлов в `data/` повторите конфигурацию и сборку CMake, чтобы
обновить данные внутри исполняемого файла.

При обычном запуске приложение пытается слушать `can0`:

```bash
./build/bga_visualizer
```

Можно выбрать другой интерфейс или отключить CAN-приём:

```bash
./build/bga_visualizer --can-interface can1
./build/bga_visualizer --can-byte-order big
./build/bga_visualizer --no-can
```

Опции можно сочетать с необязательными путями к STL и CSV: `bga_visualizer [model.stl] [sensors.csv] [--can-interface NAME] [--can-byte-order little|big] [--no-can] [--forced-can]`.

## Работа с Git

Основной рабочий процесс: разработка на компьютере, отправка изменений в GitHub,
затем получение изменений и пересборка на Raspberry Pi.

## Разработка на macOS (Visual Studio Code)

Установите Xcode Command Line Tools, Homebrew и расширение C/C++ для VS Code.
В терминале установите SDL2 и CMake:

```bash
xcode-select --install
brew install cmake sdl2
```

Из терминала VS Code, открытого в корне проекта, соберите и запустите:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/bga_visualizer
```

## Разработка на Windows (Visual Studio Code)

### Предварительные требования

Установите следующее ПО:

1. **Visual Studio 2022 Community** (или Visual Studio Build Tools) с нагрузкой
   **Разработка классических приложений на C++** (_Desktop development with C++_).
   Это даст компилятор MSVC, линковщик и генератор CMake для Visual Studio.
2. **CMake** (https://cmake.org/download/) — добавьте `cmake.exe` в PATH.
3. **Git** (https://git-scm.com/download/win) — добавьте `git.exe` в PATH.
4. **VS Code** с расширением **C/C++** (опционально).

### Установка SDL2 через vcpkg

Откройте PowerShell и выполните:

```powershell
git clone https://github.com/microsoft/vcpkg "$env:USERPROFILE/vcpkg"
& "$env:USERPROFILE/vcpkg/bootstrap-vcpkg.bat"
& "$env:USERPROFILE/vcpkg/vcpkg.exe" install sdl2:x64-windows
```

### Сборка приложения

Из корня проекта выполните настройку и сборку через CMake:

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:USERPROFILE/vcpkg/scripts/buildsystems/vcpkg.cmake" -A x64
cmake --build build --config Release
```

Ключ `-A x64` явно указывает 64-битную сборку (совместимую с `sdl2:x64-windows`).

### Запуск приложения

На Windows CAN-приём выключен по умолчанию (SocketCAN доступен только в Linux).
Запуск без CAN:

```powershell
.\build\Release\bga_visualizer.exe
```

Для принудительного включения CAN используйте `--forced-can` в командной строке
или `forced-can=1` в файле `config.txt`:

```powershell
.\build\Release\bga_visualizer.exe --forced-can
```

Явное выключение CAN через `--no-can` (избыточно на Windows, так как выключен по
умолчанию, но доступен для ясности):

```powershell
.\build\Release\bga_visualizer.exe --no-can
```

### Важно: SDL2.dll

Для запуска `bga_visualizer.exe` рядом с ним должен находиться `SDL2.dll`.
Скопируйте его из каталога установки vcpkg:

```powershell
Copy-Item "$env:USERPROFILE\vcpkg\installed\x64-windows\bin\SDL2.dll" ".\build\Release\SDL2.dll"
```

Если вы запускаете программу из другой рабочей директории, убедитесь, что
`SDL2.dll` доступна в PATH или лежит рядом с `.exe`.

### Параметры командной строки

```
bga_visualizer.exe [model.stl] [sensors.csv] [--can-interface NAME] [--can-byte-order little|big] [--no-can]
```

Без аргументов используются встроенные в исполняемый файл модель и список датчиков.
На Windows всегда запускайте с `--no-can`.

### Файл конфигурации `config.txt`

В корне проекта находится файл `config.txt`, в котором хранятся настройки
приложения. Программа загружает его при запуске и сохраняет при закрытии.

Формат файла:

```
# 1. Параметры запуска программы
no-can=1
can-ids=0x3C0

# 2. Углы просмотра для кнопки "AUTO PERSPECTIVE" (в градусах)
auto-perspective-heading=70.0
auto-perspective-pitch=-44.5
auto-perspective-distance=18.0

# 3. Начальные значения ползунков (0.0 .. 0.95)
model-transparency=0.0
model-z-offset=0.0

# 4. Список выключенных kernel (номера от 0 до 34, через запятую)
disabled-kernels=
```

- `no-can=1` отключает CAN, `no-can=0` включает его. Аргумент `--no-can`
  имеет приоритет над настройками файла; `--forced-can` включает CAN.
- `can-ids` — список от 1 до 10 стандартных CAN-ID в диапазоне `0x000–0x7FF`,
  разделённых запятыми. Указывайте значения в десятичной форме или с префиксом
  `0x`; по умолчанию используется `can-ids=0x3C0`. Пример: `can-ids=0x3C0,0x3C1`.
  Некорректный список целиком игнорируется, и используется `0x3C0`.
- `auto-perspective-*` — углы и расстояние, которые применяются при нажатии
  кнопки **AUTO PERSPECTIVE**.
- `model-transparency` и `model-z-offset` — начальные значения ползунков
  прозрачности модели и смещения по оси Z.
- `disabled-kernels` — список номеров kernel (от 0 до 34), которые должны быть
  скрыты при запуске. Например, `disabled-kernels=1,5,7` скроет kernel 1, 5 и 7.
  При закрытии программы список обновляется из текущего состояния интерфейса.

### Пересборка после изменений

После изменения исходников или файлов в `data/` можно пересобрать проект
вручную двумя командами CMake (настройку и сборку), либо использовать
готовый скрипт `rebuild.ps1`, который делает всё автоматически:

```powershell
.\rebuild.ps1
```

Скрипт:

1. Закрывает запущенный экземпляр `bga_visualizer.exe` (если есть),
2. Выполняет конфигурацию CMake с vcpkg toolchain-файлом,
3. Собирает проект в режиме Release,
4. Копирует `SDL2.dll` из vcpkg рядом с исполняемым файлом.

Скрипт `rebuild.sh` предназначен только для Linux.

## Внешние данные

По умолчанию приложение использует модель STL и CSV, встроенные при сборке.
Их можно заменить, передав оба пути:

```bash
./build/bga_visualizer path/to/model.stl path/to/sensors.csv --no-can
```
